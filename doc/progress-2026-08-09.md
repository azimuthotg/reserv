## 4. แก้สคริปต์แคปหน้าจอที่รันไม่ได้มาตลอด

[doc/capture_external_shots.py](capture_external_shots.py) มีคำสั่งแคป `staff_13c_external_edit` อยู่แล้ว
และ [doc/make_external_report_docx.py:265](make_external_report_docx.py) ก็เรียกภาพนี้ **แต่ไฟล์ภาพไม่เคยมี**

⚠️ **ทำไมไม่มีใครรู้:** `manual_style.figure()` เจอไฟล์ไม่ครบจะ `print("ข้าม")` แล้วไปต่อเงียบ ๆ
→ [external-access-report.docx](external-access-report.docx) ที่แจกไป **มีหัวข้อ "แก้ไขข้อมูลสมาชิก" แต่ไม่มีภาพ**

**สาเหตุที่แคปไม่ได้:** playwright ใน WSL Ubuntu เป็น 1.58.0 ซึ่งมองหา chromium **revision 1208**
แต่ที่ติดตั้งไว้จริงคือ **1217** → `pw.chromium.launch()` ล้มด้วย `Executable doesn't exist` ทุกครั้ง
([check_booking_form.py](check_booking_form.py) เลี่ยงปัญหานี้ด้วยการ hardcode `executable_path` ไว้)

**แก้:** เพิ่ม `chromium_path()` ที่หา binary เองจาก `~/.cache/ms-playwright/chromium-*/` (เอาตัวใหม่สุด)
แล้วส่งเข้า `launch(executable_path=..., args=["--no-sandbox"])` — ถ้าหาไม่เจอค่อยปล่อยให้ playwright จัดการเอง
พร้อมแก้ข้อความท้ายสคริปต์ที่ยังอ้างชื่อไฟล์เก่า `make_external_manual_docx.py` (เปลี่ยนชื่อไปตั้งแต่ 7 ส.ค.)

**ทดสอบแล้ว:** เปิด chromium 1217 ได้ · เข้า `/manage/login/` ได้ · เจอช่อง username/password ครบ

```powershell
# เหลือขั้นตอนเดียว — ต้องใช้รหัส staff จึงให้ผู้ใช้รันเอง
```

## 4.1 ขยายขนาด QR code ทุกช่องทาง (งานค้างจาก inbox 23 ก.ค.)

เดิม 5 หน้า hardcode ขนาดคนละค่า → รวมมาไว้ที่ helper กลาง
[booking/static/booking/js/qr.js](../booking/static/booking/js/qr.js) — `NPUQr.render(el, text, {reserve, max})`

| หน้า | เดิม | ใหม่ (จอ 375px) | ใหม่ (จอ 320px) |
|---|---|---|---|
| `/card/` · `/card-login/` | 180 | **279** (+55%) | 224 |
| `/external/` · `/external/permanent/` | 200 | **271** | 216 |
| `/manage/external/<id>/` (staff) | 160 | **240** | 200 |

- ขนาดคิดจาก `window.innerWidth` ลบ padding ของแต่ละหน้า (`reserve`) แล้ว clamp ที่ 200–320 px
- วาดที่ **ความละเอียด 2 เท่า** แล้วย่อด้วย CSS → ขอบโมดูลคมบนจอ retina
- เพิ่ม/ลดขนาดทั้งระบบภายหลังให้แก้ `MIN_PX`/`MAX_PX` ในไฟล์เดียว

### กับดักที่เจอระหว่างทาง (บันทึกใน MEM.md)

qrcodejs วาดลง `<canvas>` แล้วสลับเป็น `<img>` — **แต่บน UA ที่เป็น Android มันไม่สลับ** (คง canvas ไว้
และปล่อย `<img>` ว่างซ่อนไว้ เพราะ `_getAndroid` อ่าน "Android 14" ไม่ออก) ถ้าตั้งขนาดด้วย JS รายโหนด
จะพลาดโหนดที่เกิดทีหลัง → เปลี่ยนไปคุมด้วย CSS ที่ตัวครอบ (`[data-npu-qr]>canvas,>img{width:100%}`)
ซึ่งครอบคลุมทั้ง 2 เส้นทาง · **ห้ามแตะ `display`** ไม่งั้น canvas ที่ถูกซ่อนจะโผล่ซ้อนกับ img

### ตรวจแล้วบนเบราว์เซอร์จริง

| viewport | ผล |
|---|---|
| 320 × 720 | 224 / 216 / 200 px · ไม่ล้นแนวนอน |
| 375 × 812 (UA Android) | 279 / 271 / 240 px · แสดงผ่าน **canvas** (เส้นทาง Android) ถูกต้อง |
| 1280 (desktop) | 320 / 320 / 240 px (ชนเพดาน) · แสดงผ่าน **img** · ไม่ล้น |

template ทั้ง 5 ไฟล์ compile + render ผ่าน และมี `qr.js` + `NPUQr.render` ครบทุกไฟล์

> **deploy:** มีไฟล์ static ใหม่ → ต้อง `collectstatic` แต่ **ไม่ต้อง restart** (ไม่ได้แก้ Python code)
