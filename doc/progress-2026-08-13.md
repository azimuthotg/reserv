## อาการที่ผู้ใช้แจ้ง

นักศึกษากดดูโปรไฟล์จาก LINE OA แล้วเห็น **รหัสของตัวเอง คู่กับชื่อของคนอื่น**
เจ้าหน้าที่ลบการผูกบัญชีที่ `apiapp_userprofile` ฝั่ง api แล้วให้ผูกใหม่ **ก็ยังผิดเหมือนเดิม**

## สาเหตุ

`/api/check-user/` ประกอบคำตอบจากสองแหล่งที่ไม่ตรงกัน:

| ฟิลด์ | แหล่ง | สถานะ |
|---|---|---|
| `userLdap` | ยิงสดไป `api.npu.ac.th/api/{lineUserId}/` ทุกครั้ง | ถูกเสมอ |
| `full_name`, `faculty` | `booking_lineuser` ที่ cache ไว้ `PROFILE_CACHE_DAYS`=30 | ค้างของเก่า |

`_get_or_refresh_line_user()` มี fast path ที่เช็คแค่ "cache เกิน 30 วันหรือยัง"
**ไม่ได้เช็คว่ารหัสที่ api ส่งมาตรงกับที่ cache ไว้หรือเปล่า** และ cache นี้ผูกกับ
**LINE userId** อยู่คนละฐานกับ api — การลบแถวฝั่ง api จึงไม่แตะมันเลย
พอผูกใหม่ ฟังก์ชันก็ `return` แถวเดิมโดยไม่ยิงไปดึงชื่อใหม่แม้แต่ครั้งเดียว

ชั้นที่สอง: `sessionStorage` (`npu_user_v2:<LINE userId>`) **ไม่มีวันหมดอายุ**
และหน้าเว็บเชื่อ `/api/access-status/` ที่ดูแค่ local row — ปิดเปิดหน้าใหม่ใน
session LINE เดิมก็ยังเห็นของเก่า

## สิ่งที่แก้

**`booking/views.py`**
- `_get_or_refresh_line_user()` รับ `force=` และยกเลิก fast path เมื่อ
  `user_ldap`/`user_type` จาก api ไม่ตรงกับที่ cache ไว้
- ดึง profile ไม่สำเร็จ + รหัสเดิม → คงชื่อเดิมไว้ ไม่เขียนทับด้วยค่าว่าง และไม่เลื่อน
  `profile_updated_at` เพื่อให้ครั้งหน้าลองใหม่ (ในฐานมีแถว `full_name` ว่างอยู่จริง
  น่าจะมาจากอาการนี้)
- `register_page()` เรียกด้วย `force=True` — เพิ่งผูกบัญชี = ต้องได้ profile สดเสมอ

**`landing.html` / `booking.html` / `card.html`**
- profile cache ใน `sessionStorage` มีอายุ 30 นาที (`CACHE_TTL_MS`) ผ่าน
  `readCache()` / `writeCache()` — ของเก่าที่ไม่มี `_ts` ถือว่าหมดอายุทันที (self-migrating)

**`booking/management/commands/refresh_profile.py`** (ใหม่)
- `python manage.py refresh_profile <ldap|LINE userId|ชื่อ>` มี `--dry-run`
- ถามการผูกล่าสุดจาก api ก่อนเสมอ เพราะรหัสที่ cache ไว้อาจเป็นของเก่า

**`booking/tests.py`** — `ProfileCacheInvalidationTests` 5 เคส:
รหัสเปลี่ยนต้อง refresh · รหัสเดิมต้องยังใช้ cache · `force=True` ต้อง refresh ·
api ล่มต้องไม่ล้างชื่อ · `check_user()` ต้องคืนรหัสกับชื่อของคนเดียวกัน
