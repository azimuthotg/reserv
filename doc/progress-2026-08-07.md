### 1. ตรวจเอกสารทั้งชุดที่เกี่ยวกับบริการบุคคลภายนอก เทียบกับ code จริง

ใน CLAUDE.md/AGENTS.md) เทียบกับ `booking/views.py`, `booking/manage_views.py`,
`booking/urls.py` และ template จริง พบ 4 กลุ่มปัญหา

| กลุ่ม | สิ่งที่พบ |

### 2. แก้เนื้อหาคู่มือ external ให้ตรง code

ผู้ใช้ยืนยันว่า QR บุคคลภายนอกทำงานปกติแล้วและแจ้งทีมประตูเรียบร้อย จึงแก้ที่สคริปต์ต้นทาง
แล้ว generate ใหม่ (ไฟล์ .docx ยังไม่เคยแก้มือใน Word จึงสร้างทับได้ปลอดภัย)

- บทที่ 2.3 และ FAQ — เปลี่ยนจาก "รอทีมประตูทดสอบ" เป็นทดสอบผ่านแล้วทั้งรายวันและถาวร
  (16 ก.ค. 2569) พร้อมลำดับการตรวจเมื่อพบเคสสแกนไม่ผ่าน
- บทที่ 3.1 — ตัดข้อความเว้นเลขบัตรสำหรับ VIP ออก ระบุว่าหน้า public บังคับ 13 หลัก
- บทที่ 4.2 — ย้ายเรื่อง VIP มาไว้ที่นี่ พร้อมอธิบายรหัสอ้างอิงขึ้นต้น `V` และข้อจำกัดว่าสมาชิก
  กลุ่มนี้เปิดดูบัตรเองที่หน้า public ไม่ได้
- เพิ่มหัวข้อแก้ไขข้อมูลสมาชิก (ชื่อ-สกุล/รูป ไม่กระทบรหัสและสถานะ) ระงับ/ลบเลื่อนหมายเลข
- FAQ เพิ่ม 2 ข้อ (VIP ไม่มีเลขบัตร / เปลี่ยนชื่อ-รูป) และภาคผนวกเพิ่ม URL หน้าเจ้าหน้าที่

### 3. เปลี่ยนรูปแบบเอกสารตามที่ผู้ใช้กำหนด

ย้ายจากสไตล์เดิม (มีสี 4 สี + กล่องคำแนะนำ/คำเตือน) ไปใช้ `manual_style.py` ชุดเดียวกับคู่มือ 2569

| ข้อกำหนด | ผลตรวจในไฟล์ที่ generate |
|---|---|
| ตัวอักษรดำทั้งหมด | สีในเอกสารเหลือค่าเดียวคือ `000000` |
| ตัวปกติ 16 เพิ่มตามลำดับ | body 16 · บท 22 · หัวข้อย่อย 19 · ชั้นสาม 17 · ในตาราง 15 · caption/เลขหน้า 14 |
| หัวตารางจัดกลาง สีเทา | พื้น `EDEDED` จัดกึ่งกลางทุกตาราง เส้น `BFBFBF` |
| ไม่เอาคำแนะนำ/คำเตือน | ไม่มี `ℹ`/`⚠` เหลือ — เนื้อหาในกล่องเดิม 7 กล่องเขียนใหม่เป็นย่อหน้าปกติ |
| ภาพขั้นตอนของเจ้าหน้าที่ | 6 ภาพ 16:9 (1920×1080) จาก production เลือกอัตราส่วนเดียวทั้งเล่ม |

### 4. แปลงเป็นรายงานประกอบการประชุม + เพิ่มบทช่องทาง `/card-login/`

ผู้ใช้ถามว่าช่องทาง login ที่ไม่ผ่าน LINE ของนักศึกษา/บุคลากรเก็บข้อมูลไว้ที่ reserv หรือ api
ตรวจ code แล้วสรุปว่า **โค้ดอยู่ที่ reserv ทั้งหมด และไม่มีการเก็บข้อมูลถาวรที่ใดเลย**
(`card_login()` `views.py:1274` → `_verify_ldap()` ยิง `/auth-ldap/auth_ldap/` ของ api → ออก QR
เป็น `user_ldap` ตัวเดียวกับ `/card/` · "จดจำ 90 วัน" เก็บแค่ `user_ldap` ใน signed cookie) แล้วนำ
ข้อมูลนี้ลงเอกสาร พร้อมแปลงเอกสารทั้งเล่มเป็นรายงาน

- เปลี่ยนชื่อไฟล์และสคริปต์ด้วย `git mv` (ประวัติไฟล์ต่อเนื่อง) ปกเป็น "รายงานประกอบการประชุม"
- ตัดสารบัญออก — เขียนปกเองในสคริปต์แทน `cover()` แล้วขึ้น section ใหม่ เพราะเดิมสารบัญเป็นตัว
  คั่น section ที่ทำให้ปกไม่มีเลขหน้า ตรวจแล้ว section 1 (ปก) ไม่มีเลขหน้า section 2 เริ่มนับที่ 1
- เพิ่มบทที่ 5 ช่องทางขอ QR สำหรับนักศึกษาและบุคลากร (5.1 ขั้นตอน + ภาพ, 5.2 ข้อมูลเก็บที่ใด,
  5.3 ขอบเขตและการควบคุมความเสี่ยง) FAQ เลื่อนเป็นบทที่ 6
- เพิ่มตารางสรุป 4 ช่องทางขอ QR ในบทที่ 1.1 · FAQ เพิ่ม 2 ข้อเรื่องคนใน · ภาคผนวกเพิ่ม
  `/reserv/card-login/`

## การตรวจสอบ

- ตรวจไฟล์ .docx ที่ generate ออกมาโดยอ่าน `word/document.xml` ตรง ๆ — สีตัวอักษรเหลือ
  `000000` ค่าเดียว, ไม่มีสัญลักษณ์กล่องเตือน, หัวตารางพื้นเทา 13 ช่อง, ไม่มี TOC field,
  2 section (ปกไม่มีเลขหน้า / เนื้อหาเริ่มหน้า 1), ฝังภาพ 6 ไฟล์
- ตรวจอัตราส่วนภาพทุกไฟล์ที่ใช้ = 1.778 (16:9) ครบทุกภาพ
- ตรวจ `git diff --ignore-cr-at-eol` ของ `booking/views.py` และ `card_login.html` แล้ว —
  ไม่มีบรรทัดใดต่างจริง เป็นการแปลง CRLF ทั้งไฟล์เท่านั้น ไม่ใช่การแก้เนื้อหา
- **ยังไม่ได้ทดสอบ:** ไม่ได้เปิดไฟล์ด้วย Word เพื่อดูหน้าตาจริงและจำนวนหน้า
