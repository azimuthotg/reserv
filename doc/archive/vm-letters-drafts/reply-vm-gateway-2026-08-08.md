# หนังสือตอบกลับ — ดำเนินการปรับข้อมูลระบบจองเรียบร้อยแล้ว

**ถึง:** ทีมพัฒนา LRS ARC VM Gateway
**จาก:** ผู้ดูแลระบบจองพื้นที่บริการ (reserv) สำนักวิทยบริการ มหาวิทยาลัยนครพนม
**วันที่:** 8 ส.ค. 2569
**อ้างถึง:** ใบแจ้งขอปรับข้อมูลระบบจอง (reserv_db) ลงวันที่ 8 ส.ค. 2569
**เรื่อง:** ตอบกลับ — เพิ่มห้อง Canva Pro 2 และปิดห้อง ChatGPT เรียบร้อยแล้ว

---

## ⭐ คำตอบที่ทีมพัฒนาต้องการ

> ## `booking_name` = **`canva2`**

ใช้ตามที่ขอมาทุกตัวอักษร ไม่มีการเปลี่ยนแปลง — ตั้ง `VMMachine.room_key = 'canva2'` ได้เลย

| 1 | เพิ่มห้อง `canva2` ตั้งค่าเหมือน `canva` | ✅ **ดำเนินการแล้ว** |

## ⚠️ ข้อควรระวัง 3 ข้อสำหรับฝั่ง Gateway

### 1. ห้อง `chat-gpt` **ยังอยู่ในตาราง** — กรุณากรอง `is_active`

ตามที่ขอมา เราปิดด้วย `is_active = 0` **ไม่ได้ลบแถวออก** (และลบไม่ได้ด้วย เพราะ foreign key
จากตาราง booking ตั้งเป็น `PROTECT` เพื่อป้องกันประวัติการจอง 16 รายการหาย)

**ดังนั้นถ้า Gateway query ตาราง `booking_room` โดยไม่กรอง `is_active` จะยังเห็นห้องนี้อยู่**
กรุณาเพิ่มเงื่อนไข `WHERE is_active = 1` ในทุกจุดที่อ่านรายการห้อง และถอด mapping ของ `chat-gpt` ออกจากฝั่ง Gateway

### 2. หนึ่งคนอาจถือ Canva 2 เครื่องพร้อมกันได้

กติกาป้องกันการจองซ้ำของระบบจองผูกกับ **ห้อง** ไม่ใช่ **ผู้ใช้**
(นักศึกษา 1 คน จองห้องหนึ่ง ๆ ได้ 1 ครั้งต่อวัน)

เมื่อมี Canva 2 เครื่องที่เป็นคนละห้อง **นักศึกษาคนเดียวจึงจอง Canva Pro 1 และ Canva Pro 2
ในวันเดียวกันได้** สำนักฯ พิจารณาแล้วเห็นว่าเป็นคนละบริการ ไม่ผิดกติกา จึงคงไว้เช่นนี้ในช่วงเวลาทำการ

แจ้งเพื่อให้ทีมพัฒนาเผื่อกรณีที่ผู้ใช้รายเดียวมีสิทธิ์เข้า VM สองเครื่องในวันเดียวกัน

### 3. `max_booking_hours` ไม่ใช่ตัวจำกัดจริง

ฟิลด์ `max_booking_hours` (ค่า 2) เป็นเพียงข้อความแสดงบนหน้ารายละเอียดห้อง
**ตัวจำกัดจริงของระบบจองคือ 3.5 ชั่วโมงต่อครั้ง** ซึ่งกำหนดไว้ในโปรแกรม ไม่ได้อ่านจากฟิลด์นี้
หากฝั่ง Gateway ใช้ฟิลด์นี้คำนวณระยะเวลา session กรุณาใช้ `start_time`/`end_time` ของ booking แทน

## ข้อตกลงเรื่อง `booking_name` — รับทราบและถือปฏิบัติ

สำนักฯ รับทราบว่า `booking_name` ของห้องที่ผูกเครื่อง VM (`canva`, `canva2`, `netflix1_vm`)
เป็นกุญแจเชื่อมระบบ **จะไม่แก้ไขโดยไม่แจ้งทีมพัฒนาล่วงหน้า**
ได้บันทึกข้อตกลงนี้ไว้ในเอกสารกำกับระบบจองแล้ว (`CLAUDE.md` หัวข้อความเสี่ยง และ `MEM.md`)

ส่วนการเปลี่ยน **ชื่อแสดง (`name`)** ถือเป็นเรื่องภายในของระบบจอง จะแจ้งให้ทราบเป็นระยะแต่ไม่ถือเป็นการเปลี่ยนสัญญา

---

## เรื่องที่ขอความอนุเคราะห์จากทีมพัฒนากลับ

**ข้อความขั้นตอนการใช้บริการ (`how_to_use`) ของห้องที่ผูก VM ทั้ง 3 ห้อง**

- ห้อง Canva ทั้งสองห้องยังเป็นขั้นตอนแบบ "เปิดเครื่องคอมพิวเตอร์ที่ให้บริการ แล้วล็อกอินด้วย Username/Password"
  ซึ่งเป็นวิธีเดิมก่อนมี Gateway
- ห้อง Netflix Pro สำนักฯ เขียนไว้กว้าง ๆ ว่า "เข้าใช้งานผ่านระบบเครื่องคอมพิวเตอร์เสมือนของสำนักวิทยบริการ"
  เพราะยังไม่ทราบ URL ที่ถูกต้อง

**ขอข้อความขั้นตอนที่ถูกต้องพร้อม URL ของเว็บ Gateway** สำนักฯ จะปรับให้ตรงทั้ง 3 ห้อง
เพื่อไม่ให้นักศึกษาสับสนเวลาถึงรอบที่จองไว้

## แจ้งเพื่อทราบ — ปรับข้อมูลห้อง `netflix1_vm` เพิ่มเติม

สำนักฯ ได้จัดระเบียบข้อมูลห้องนี้ให้เข้าชุดกับห้องอื่นด้วย (ทั้งหมดเป็นฟิลด์ที่**ไม่กระทบ Gateway**):

| ฟิลด์ | เดิม | ใหม่ |
|---|---|---|
| `name` | netflix1 | **Netflix Pro** |
| `location` | Online | ออนไลน์ (ใช้งานผ่านเว็บ) |
| `description` / `facilities` / `rules` / `how_to_use` / `eligible_users` | ข้อความร่าง | เขียนใหม่ให้เป็นรูปประโยคเดียวกับห้องอื่น |

**`booking_name = netflix1_vm` คงเดิมทุกตัวอักษร** ไม่ต้องแก้อะไรฝั่ง Gateway

## สิ่งที่สำนักฯ กำลังดำเนินการต่อ

- ปรับปุ่มใน LINE OA Rich Menu — เปลี่ยนปุ่ม "ChatGPT" เป็น "Canva Pro 2" (`?room=canva2`) และปรับป้ายปุ่ม Canva เดิมเป็น "Canva Pro 1"
- ตรวจ QR code / ป้ายประชาสัมพันธ์ที่ยังชี้ไปห้อง ChatGPT

## ขั้นตอนถัดไปของทีมพัฒนา

1. ตั้ง `VMMachine.room_key = 'canva2'` ให้เครื่อง vm-canva2
2. ถอด mapping ของ `chat-gpt` ออก
3. รัน `python manage.py check_booking_mapping` เพื่อยืนยันว่าเชื่อมกันครบทุกห้อง
4. เพิ่มเงื่อนไข `is_active = 1` ในการอ่านรายการห้อง (ตามข้อควรระวังข้อ 1)

หากพบว่าเชื่อมไม่ติดหรือข้อมูลไม่ตรง แจ้งกลับได้ทันที
